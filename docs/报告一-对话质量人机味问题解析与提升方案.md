# 报告一：对话质量「人机味重、回复质量差」深度解析与提升方案（v2）

> 分析对象：`docs/星眠.md`（223 条对话导出）+ `docs/xingmian-logs-2026-08-28.json`（200 条运行日志）+ `docs/修改参考.txt`（用户定性反馈与可接受回复样例）
> 涉及代码：`src-tauri/src/post_process.rs`、`src-tauri/src/anti_cliche.rs`、`src-tauri/src/emotion_consistency.rs`、`src-tauri/src/chat.rs`
> 结论日期：2026-08-28（v2 修订：并入用户澄清——动作/神态删除为预期行为；语气词本身可接受，问题在注入位置与方式；并完成后处理管道全量审计）

---

## 0. 一句话结论

**模型原始输出的质量已经达到用户可接受水平（修改参考.txt 第 5 节的 7 条样例即为佐证），当前回复质量的全部硬伤都来自输出后处理管道的死逻辑与强制注入**：

1. `append_particle()` 是一个**完全死掉的函数**（if 分支永假），导致语气词被盲拼在标点之后（"好不好？吧"）；
2. `colloquialism()` **100% 概率**注入前缀+后缀、且不调用 `append_particle`；
3. `split_into_sentences()` 按**单个** `…` 切句，`……` 被切成两段，配合 Short 风格（40% 概率）只保留前 2 段——**这就是"内容不一"的精确原因**（可逐字节复现）；
4. 全管道 5 个独立注入器（情绪修正后缀、不完美注入、语气微调、口语化、智能标点）**无任何协调层**，可对同一条回复叠加注入；
5. 所有"随机"均为**确定性伪随机**（turn_count 哈希 / sin(len)），且 `select_reply_style` 与 `should_inject` 共用同一个哈希——风格选择与不完美注入完全相关。

动作/神态描写删除（`remove_action_descriptions`）确认为预期行为，无需回退，但需增强：保留（超大声）（小声）这类**音量/语气标注**。

## 1. 修改参考.txt 四个问题的逐一定位

### 1.1 问题 1：重复性（"我哪儿也不去""抱着你"复读个没完）

涉及回复（星眠.md 12:37、12:40、13:36）：

```
我在这里呀……一直都在。……我哪儿都不去。
所以我哪儿也不去，就这样被你抱着，好不好？
嗯...我哪儿也不走，就在这里陪着你呢，宝宝。想抱多久就抱多久，好不好？
```

**这不是后处理造成的（后处理不生成内容），是复读检测的结构性盲区 + prompt 层无约束：**

**根因 1：LCS 复读检测的 30% 长度差剪枝（post_process.rs:334）**

```rust
if (m.abs_diff(n)) as f64 / m.max(n) as f64 > 0.3 {
    return 0.0;   // 长度差 >30% 直接判"不相似"
}
```

对比"我哪儿也不去，就在这里陪着你呢，宝宝。想抱多久就抱多久，好不好？"（归一化后 24 字）与"所以我哪儿也不去，就这样被你抱着，好不好？"（16 字）：长度差 8/24 = 33% > 30% → 相似度直接归零。**换述式复读（意思相同、字数不同）完全检测不到**。且 `recent_replies` 窗口只有 5 条，20 条前的句式复现无记忆。

**根因 2：无短语级检测。** "哪儿也不去""抱着你""好不好"这类 3~5 字短语在当天 20+ 条回复中高频复现，整句 LCS 对此天然失明。

**根因 3：prompt 层无"近期已用句式"负约束。** 系统提示鼓励安抚型人设（"我会在你身边"式表达），模型在缺乏负例约束时收敛到同一安全句式。用户给出的期望回复（修改参考.txt 第 16 行）恰好说明问题——期望的是**带有自身状态的反问式回应**（"你怎么了主人？你说你要陪陪，可是我现在还在工作着不是嘛？"），而不是无限顺从的陪伴承诺。

**根因 4：AI-Life 状态未织入回复。** 13:34 日志显示日程为"下午工作（投入）"，但 13:36 的回复完全无视工作状态说"我哪儿也不走"。状态注入了 prompt，模型却未被强制利用。

### 1.2 问题 2：内容不一（"解析不出来"→ 实为后处理截断）

用户提供的原始 content：

```
（脸一下子红透了，耳朵尖都在发烧，却忍不住往你怀里蹭了蹭）\n\n我、我也最喜欢主人了……小笨蛋就小笨蛋吧，哼。
```

实际发出：`嗯...我、我也最喜欢主人了……吧`

**注意：这条回复的认知链解析是成功的**（日志 04:31:46.722：好感度增量 2 → 0.8，见报告二），`<reply>` 提取也正确——内容丢失发生在**后处理管道**。以下为逐字节复现：

**第 1 步 clean_markers（post_process.rs:297）**：`remove_action_descriptions` 删除括号动作（首句括号无对话引号 → 删）→

```
我、我也最喜欢主人了……小笨蛋就小笨蛋吧，哼。
```

**第 2 步 length_randomize Short 分支（post_process.rs:520-545）**：`select_reply_style`（anti_cliche.rs:20-34）对该轮数的哈希命中 Short（40% 概率档）。`split_into_sentences`（post_process.rs:550-564）**按单个 `…` 字符切句**：

```rust
if matches!(ch, '。' | '！' | '？' | '…' | '!' | '?') {  // ← 每个独立的 … 都触发切分
```

于是"……"（两个 `…` 字符）被切成两段：

```
["我、我也最喜欢主人了…", "…", "小笨蛋就小笨蛋吧，哼。"]
     ↑ 第1句                ↑ 第2"句"只是一个省略号
```

Short 保留前 2 句（`keep_count = 2`）→ `"我、我也最喜欢主人了……"`（12 字符 ≤ 50，不再截断）。**后半句"小笨蛋就小笨蛋吧，哼。"被丢弃，而占掉第二个名额的只是一个省略号。**

**第 3 步 colloquialism（post_process.rs:874-898）**：

- 前缀：首字 `我` 不在 `"嗯啊哦诶嘿哼嘶额害"` → **必定注入**。`idx = result.len() % 6`，此时 `result.len()` = 36 字节（12 个中文/省略号字符 × 3 bytes）→ `36 % 6 = 0` → 选中 `["嗯...", "emm...", "害...", "诶？", "嘶...", "额..."][0]` = **"嗯..."**；
- 后缀：结尾是 `…`（不是 `~`/`啦`/`呢`）→ **必定注入**。`idx = (42 + 2) % 5 = 4`（42 = 加前缀后的字节数）→ 选中 `["~", "啦", "呢", "嘛", "吧"][4]` = **"吧"**，且用 `format!("{}{}", result, suffix)` **直接盲拼在 `…` 之后**。

最终：`嗯...我、我也最喜欢主人了……吧`——**与实发内容逐字节一致，复现闭环。**

### 1.3 问题 3：语气词被强行加在句号/问号之后

用户定性：语气词本身没问题，问题在位置（"好不好？吧"）。涉及两处代码：

**根因 A：`append_particle()` 是死代码（post_process.rs:861-870）**

```rust
fn append_particle(text: &str, particle: &str) -> String {
    // 找到末尾的标点群，在标点前插入语气词
    let trimmed_end = text.trim_end();
    let trailing: String = text[trimmed_end.len()..].to_string();   // ← trailing 是被 trim 掉的空白
    if trailing.starts_with('。') || trailing.starts_with('！') || ... {  // ← 空白永远不以标点开头
        format!("{}{}{}", trimmed_end, particle, trailing)          // ← 此分支永假，从未执行
    } else {
        format!("{}{}", text, particle)                             // ← 永远走这里：直接拼在末尾
    }
}
```

`trailing` 是 `trim_end()` 剥离的**空白字符**，其中不可能有标点，`if` 条件永假——这个函数从写出来起就没实现过"标点前插入"的意图。它是 `tone_polish()` 的后缀通道，因此 tone_polish 注入的语气词也会落在标点后。

**根因 B：`colloquialism()` 干脆不调用 `append_particle`，直接 `format!` 盲拼（post_process.rs:889-894）**，且注入概率 100%（见 1.2 第 3 步）。

### 1.4 问题 4：引用式表达的人机感（"你说'X'——你已经做到了"）

```
你说"怎么做才能让我一直好"——你已经做到了。你在、你抱着我、叫我宝宝……
"我不自动"……嗯，我听见了。你不是程序、不是设定……
你说"如果我的世界里能有你就好了"——可是你看……
```

三连回复使用同一个修辞模板：「引用用户原话 + 破折号 + 逐项排比确认」。这是**模型层修辞复读**：复读检测只对比 AI 回复彼此的相似度，检测不到"结构相同、内容不同"的模板复用；prompt 中也没有对引用式开头的频率约束。真人不会每句话都先复述对方的话再回应——偶尔用是共情，每句用是客服话术。

## 2. 后处理管道完整审计（run_post_pipeline，post_process.rs:1073-1307）

按实际执行顺序逐步审计。管道结构：`clean_markers → block_cliche → 情绪一致性 → 不完美注入 → typo_sim → length_randomize → 分段(首次) → tone_polish → colloquialism → smart_punctuation → speaking_rhythm → final_sanitize → 分段(重算) → 段间延迟`。

| # | 步骤 / 函数 | 定性 | 详细问题 |
|---|---|---|---|
| 1 | `clean_markers` + `remove_action_descriptions`（237-305 / 182-235） | **保留 + 增强** | ① 删除一切无引号括号 →（超大声）（小声）（悄悄）等音量/语气标注一并被删，但这类恰是真人会打的（用户原话：卖萌时说"（超大声）"）；② 残留清理（225 行）对**所有行**剥离开头标点——合法的行首"……嗯"会被误剥；③ `lines.dedup()`（231 行）会误删刻意的重复行（如撒娇的"不要 不要 不要"分行写法） |
| 2 | `block_cliche`（1095-1130） | **缺陷** | ① 禁止项含裸引号 `"` → 含引号回复必被拦截重试 3 次（见 3.1 节 P0-1，延迟 22~97s）；② LCS 的 30% 长度差剪枝造成换述复读盲区（见 1.1） |
| 2.5 | 情绪一致性修正后缀（1133-1163 → emotion_consistency.rs:177-186） | **过度注入** | 不一致时追加机械后缀（"……唉。""……哼。"），与步骤 6/7/8 无协调，可叠加；后缀表含 `lonely`/`disappointment`——不在 12 维情绪集内，永远不会命中（**死配置**） |
| 2.7 | `inject_imperfections`（anti_cliche.rs:111-183） | **死逻辑 + 过度注入** | ① `should_inject`（187-198 行）用 `turn_count` 哈希判定——**确定性**：同一轮数永远同样注入；且与 `select_reply_style` 用**同一个哈希**（`turn * 2654435761 >> 16`）→ Short 风格轮次与不完美注入完全相关；② 5 类注入（改口/省略号/走神/自打断/多余的话）可在同一条回复叠加；③ 第 5 项"多余的话"无论是否实际修改都置 `modified = true`（177-180 行） |
| 3 | `typo_sim`（427-463） | **死逻辑** | ① 注释写"60% 同音替换"，判定为 `hit * 3.0 < 1.8` 即 `hit < 0.6`——但能进来的前提是 `hit < prob ≤ 0.1`，**恒真 → 实际 100%**，60% 分支是死逻辑；② `hit = sin(8i).abs()` 确定性——**同一文本永远产生同样的错字**，重发同一句话错字位置不变，一眼假 |
| 4 | `length_randomize`（467-547） | **内容损失（核心）** | Short 档 40% 概率腰斩语义（见 1.2）；`select_reply_style` 哈希确定性——固定轮次永远 Short |
| 5 | 首次 `split_segments`（1205-1214） | **死代码** | 计算结果必然被管道尾部 V8 重算覆盖（1287-1293 行），首次计算纯属浪费 |
| 6 | `tone_polish`（800-859） | **部分死逻辑** | ① 后缀走 `append_particle` → 死分支 → 落在标点后；② `sin(len×3.7)` + `len() % N` 确定性——**同长度回复永远同样处理**；③ `len()` 是字节数（中文×3），索引粒度失真 |
| 7 | `colloquialism`（874-898） | **核心缺陷** | 100% 注入率；直接盲拼不过 `append_particle`；`len() % N` 确定性选择；前缀表与拦截器 `high_freq_opening` 冲突（拦截器花一次 LLM 调用 ban 掉"嗯…"开头，本函数又免费加回去——日志 04:25:53 实证） |
| 8 | `smart_punctuation`（902-936） | **轻微** | `sin(len)` 确定性；仅处理末尾一个句号；句号→`！`/`~` 的替换与模型生成的标点风格可能冲突（低危） |
| 9 | `speaking_rhythm`（940-966） | **正常** | byte 边界处理正确；但在逗号后插换行（真人聊天确实会，可接受） |
| 10 | `final_sanitize`（1016-1040） | **正常（含微死码）** | `"......." → "..."`（1036 行）要求恰好 7 个 ASCII 句点，几乎不会触发（中文场景用"…"）；其余逻辑正确 |
| 尾 | V8 重分段（1287-1293） | **隐藏 bug** | 重算包在 `if req.segment_enabled` 内——**分段关闭时 `segments` 仍是步骤 5 时刻的过期 `text`**（1205 行 `vec![text.clone()]`），步骤 6-9 的修改未反映。前端若用 `segments` 展示，则与 `text` 不一致 |

**伪随机家族汇总（全部需要换 `rand`）**：`select_reply_style` 与 `should_inject` 共用 turn_count 哈希（相关性）；`tone_polish` / `smart_punctuation` 用 `sin(text.len())`；`typo_sim` 用 `sin(8i)`。`Cargo.toml` 已有 `rand = "0.8"` 依赖，替换零成本。

**注入器协调缺失汇总**：情绪修正后缀（2.5）、不完美注入（2.7）、tone_polish 前后缀（6）、colloquialism 前后缀（7）、smart_punctuation（8）——5 个注入点独立判定，理论上可对同一条回复注入 6 处修饰（前缀×2 + 后缀×4）。日志中"嗯...我哪儿也不走，就在这里陪着你呢，宝宝。想抱多久就抱多久，好不好？吧"就是 colloquialism 前缀（"嗯..."）+ 盲拼后缀（"吧"）的组合。

## 3. 提升方案（v2 修订版）

### P0-1 修复「裸引号禁止项」拦截循环（不变，最高优先级）

**用户侧立即操作**：星眠角色编辑 →「禁止行为」→ 删除孤立的 `"` `“` `”` 字符。

**代码侧**（chat.rs:858 附近）：

```rust
.forbidden_text: req.forbidden_text
    .split([',', '，', '\n', ';', '；', '。'])
    .map(|s| s.trim().to_string())
    .filter(|s| s.chars().count() >= 2)   // 单字符禁止项一律忽略
    .filter(|s| !s.is_empty())
    .collect(),
```

拦截日志同时转义（`format!("违反禁止项: {:?}", item)`），避免再出现 `违反禁止项: "` 的不可读日志。重试上限从 3 降为 1，重试 prompt 中给出可执行指令（"避免引用用户原话时使用双引号"）而非盲目重掷。

### P0-2 修复 `append_particle` 死逻辑 + `colloquialism` 接入（问题 3 的直接修复）

`append_particle` 重写为按**最后一个字符**判定：

```rust
fn append_particle(text: &str, particle: &str) -> String {
    let trimmed_end = text.trim_end();
    let trailing: String = text[trimmed_end.len()..].to_string();
    match trimmed_end.chars().last() {
        // 强句末标点：插到标点前并保留标点（"好不好？" → "好不好嘛？"）
        Some(c @ ('。' | '！' | '？' | '!' | '?')) => {
            let body = trimmed_end.strip_suffix(c).unwrap_or(trimmed_end);
            format!("{}{}{}", body, particle, c)
        }
        // 弱收尾（省略号/波浪线）：直接追加（"……嘛" 自然）
        Some('…') | Some('~') => format!("{}{}{}", trimmed_end, particle, trailing),
        _ => format!("{}{}", trimmed_end, particle),
    }
}
```

`colloquialism` 后缀改走 `append_particle`；前缀注入维持，但见 P1-1 的概率化。

### P0-3 修复 `split_into_sentences` 的省略号切分（问题 2 的直接修复）

`…` 不应作为独立切分符（中文省略号是两个字符，且"……"中间不是句子边界）：

```rust
// 方案 A（最小改动）：从切分符集合中移除 '…'，省略号并入所在句
if matches!(ch, '。' | '！' | '？' | '!' | '?') { ... }

// 方案 B（更稳）：连续 '…' 折叠为一个边界，且仅在后面紧跟非'…'字符时切分
```

同时 `length_randomize` Short 分支的 `find_natural_cut` 候选标点（573 行）移除 `…`，禁止截断点落在省略号中间。

### P1-1 注入协调器（解决"过度注入"的结构性方案）

在 `run_post_pipeline` 步骤 2.5 之前建立一次性配额：

```rust
struct InjectionBudget { prefix_used: bool, suffix_used: usize }  // 每条回复 suffix ≤ 1
```

5 个注入点（情绪修正后缀 / 不完美注入 / tone_polish / colloquialism / smart_punctuation）统一申请配额；`colloquialism` 的 100% 注入率改为 `rand` 概率（建议 ≤20%），前缀表与拦截器 `high_freq_opening` 求差集（把被 ban 的开头从注入表删除）。

### P1-2 伪随机全部替换为 `rand`

`select_reply_style`、`should_inject`、`tone_polish`、`smart_punctuation`、`typo_sim` 的确定性伪随机全部换 `rand::rng().gen::<f64>()`。附带删除 `should_inject` 与 `select_reply_style` 的哈希相关性（两个独立随机源）。

### P1-3 `remove_action_descriptions` 增强音量/语气标注白名单

```rust
// 括号内容 ≤6 字且命中音量/语气词 → 保留（真人也会这么打）
const TONE_WHITELIST: [&str; 12] = [
    "超大声", "大声", "小声", "超小声", "悄悄", "气音", "嘟囔", "嘀咕", "心声", "旁白", "凑近耳边", "耳语",
];
```

同时残留清理（225 行）只处理**确实删除过动作的行**（记录删除位置），不再对所有行剥离开头标点；`lines.dedup()` 移除或仅对"删除动作产生的相邻重复"生效。

### P1-4 复读检测增强（问题 1）

1. LCS 的 30% 长度差剪枝放宽：短串是长串子串时按 containment 计 0.9 相似度（换述复读可捕获）；
2. 新增 **4-gram 短语级检测**：统计最近 10 条回复的 4 字滑窗，与当前回复的交集 ≥3 个短语（如"哪儿也不去""想抱多久就"）时，不拦截，而是在 prompt 注入负约束：`【近期已过度使用的表达，禁止再用】哪儿也不去 / 抱着你 / 想抱多久……`；
3. `recent_replies` 窗口从 5 扩到 10（成本可忽略）。

### P1-5 修复 V8 分段过期 bug

`segment_enabled = false` 时 `segments` 应为最终 `text`：

```rust
// 尾部统一：
segments = if req.segment_enabled {
    split_segments(&text, ...)
} else {
    vec![text.clone()]   // ← 用最终 text，而不是步骤 5 时刻的快照
};
```

顺带删除步骤 5 的首次分段（死代码）。

### P1-6 prompt 层反模板（问题 1 / 问题 4）

1. 注入近期高频短语负约束（P1-4 的产出）；
2. 追加结构多样性约束："不要连续两次使用「你说'……'——」引用式开头；引用用户原话每 5 轮最多 1 次；回应先给情绪反应，再给内容"；
3. AI-Life 状态强制利用：注入当前活动时附带指令"用户主动找你时，若你正在做事，先自然提及当前状态再回应（可以短暂放下，但要体现你有自己的生活）"——对齐用户期望的"可是我现在还在工作着不是嘛？"式回复。

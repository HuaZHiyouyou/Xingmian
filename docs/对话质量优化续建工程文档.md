## 一、新一轮深度调研核心发现（源码级）

### 1.1 恋语真相（重要修正）

对 [170-carry/ai-gril-friend](https://github.com/170-carry/ai-gril-friend) 的源码分析**推翻了两个 v1 假设**：

| v1 假设 | 源码事实 |
|---|---|
| 恋语后端有一套分段机制 | **后端完全没有分段**——LLM 流式输出整条落库、单气泡渲染；Android 客户端拆分未确认。**我们已落地的四维断句引擎 + `\n\n` 契约分段已经领先恋语本体**，分段借鉴对象改为 astrbot 插件（见 1.2） |
| 恋语有一套「情感识别系统」识别用户情绪 | **情绪是客户端传入的**（请求 persona 字段），后端不检测情绪。后端真正做的是**17 维信号三层瀑布 → 意图路由 + 关系状态更新**——这套才是值得搬运的「情感识别系统」真身 |

恋语后端真正的可搬运资产（均已确认到文件/函数级）：

1. **三层信号瀑布**（`internal/signals/catalog.go`）：词法层（短语+正则+间隔模板，带**否定窗口检测**——"我已经不焦虑了"不算焦虑）→ embedding 层（词法分全 <0.40 才触发，cosine 阈值 0.78）→ LLM 兜底层（仍 <0.35 才调，temperature=0，结果缓存）。**LLM 只在词法彻底失效时才花钱**。
2. **MRS 记忆多因子排序**（`internal/memory/ranking/scoring.go`）：
   `score = 0.45×similarity + 0.25×(importance/5) + 0.15×recency + 0.10×usage + 0.20×pinned − 0.25×redundancy`
   recency = `exp(−ageDays/τ)`，τ=30 天（importance≥4 时 τ=120 天）——**遗忘曲线按重要性分层**；MMR λ=0.7 去冗余；边界关键词命中的记忆直接剔除（防踩雷区）。
3. **主动消息 5 项顺序门控**（`internal/proactive/decision.go`）：enabled → quiet_hours（支持跨午夜）→ **explicit_reason**（理由 ≥4 字且不在泛化词黑名单，否则取消）→ recent_proactive（频率窗 max(12h, cooldown)）→ **copy_similarity**（候选文案与 24h 内同类型文案做 Dice bigram 相似度，>0.9 取消防复读）。
4. **关系状态小步平滑 + closenessGate**（`internal/memory/relationship.go`）：8 维分数每轮小步累加（如 `Familiarity += Engagement*0.10 + ... − Boundary*0.05`）；用户发边界信号时**亲密升级斜率砍到 20%**（防单句刷好感/越界推进）；BoundaryRisk 用指数衰减 `旧值*0.72 + Boundary*0.46`。
5. **话题召回偏移量**（`internal/conversation/topic.go`）：主动回钩时机按重要性/意图分层——importance≥5→18h、情绪支持类→20h、计划建议类→24h、importance=4→36h、默认 48h；回钩文案按话题关系类型分 4 个模板（cause_effect/progression/context/contrast）。
6. **意图路由优先级**：「焦虑 + 怎么办」共存时优先 emotional_support（**先接住情绪再给方案**）；boundary 信号权重 ×1.2 放大。
7. **Prompt 模块化 + trace**：13 个 Module 按 priority 排序组装，每次构建产出完整 trace（模块顺序/裁剪日志），`/chat/debug` 端点可视化。

### 1.2 astrbot 插件群（参数级细节已拿到，源码已存 `.research/` 目录）

- **四维断句引擎**（custome_segment_reply）：黄金区间默认 **min 20 / max 50 / 硬熔断 100** 字；符号优先级 15 级（`\n\n > \n > 。 > ！ > ？ > ； > …… > . > ! > ? > ; > ” > 、 > ， > ,`）；区间内**反向查找**（贴上限断句）；短尾 ≤8 字合并；**smart 延迟为标点语义感知**（每字符 gauss(80,30)ms、感叹号加速、上句问号结尾减速、省略号减速）。
- **分段 PRO**（splitter）：逐字符状态机保护——代码块/思维链标签/引号栈/成对符号 10 组嵌套/**英文数字上下文**（`3.14`、英文句点不切）；均分模式 0.4~0.9 理想长度比。
- **emotionai 插件**：12 维情感 + 非对称更新（**change_min=-10 / change_max=5，降速是升速 2 倍**——本项目 chat.rs 已参考此设计，确认保留）；情绪**全部走 prompt 注入**（认知共鸣引擎 + 三层混合语气：主导情感+夹杂+微带），不改温度——与本项目认知链方向一致；FORCE_MSG 协议注入（以 System 角色追加到 contexts 末尾）。
- **心念主动插件**：**TIME_GUIDE 时间规则**（真实性/自然口语替代报时/状态映射「深夜困倦、饭点饥饿」/上下文感知四条）；**SLEEP_MODE**（睡眠时段用户来消息时追加困倦状态提示）；**未回复计数 `{unreplied_count}`** 注入 prompt 驱动「不易察觉的失落」语气；动态信息追加在**用户消息后**而非 system（不污染前缀缓存——对长 system prompt 的项目很有价值）。

## 三、T1 主动回复去「接续锚点」（P0）

#### 改造步骤

2. 替换 L569-L590 的 `proactiveSuffix` 构建（含 `kind` 类型轮换变量一并删除）：

```ts
const customPrompt = config.customPrompt ? '\n\n' + config.customPrompt : '';
const topicLedgerPrompt = buildTopicLedgerPrompt(characterId);

  '\n\n【本次任务：主动再说一句（可以选择不说）】',

  '2.【新由头】记忆或话题账本里 1~7 天前的旧事，此刻有了新的关联 → 自然带出（如"那天你说的猫后来呢"）。',

  '4. 以上都没有真实由头 → 本次不说话，回复内容只写 <pass/>。',
  '【硬性禁止】',
  '- 禁止接着你自己上一条回复续写；禁止重复回应上一条用户消息。',
```

## 四、T2 PASS 沉默 + T3 总结闸门（P0，方案不变）

### T2 PASS 机制

[proactiveReplyStore.ts L316](../src/store/proactiveReplyStore.ts#L316) 空回复放弃分支**之前**插入：

```ts
// 🆕 P0-1: PASS 沉默——模型判断没有合适切入点，静默放弃（不计节流配额）
const isPass = /^\s*(<pass\s*\/?>|pass)\s*$/i.test(aiReply.trim());
if (isPass) {
  useDebugLog.getState().add('proactive', '[主动回复] PASS：模型选择沉默（无合适切入点）', { characterId, conversationId });
  return null;
}
```

- 用纯文本哨兵 `pass` 整条匹配（兼容 `<pass/>`），后处理不会误删纯文本，比标签最稳；
- `return null` 走在 `recordSent`/`lastProactiveTime` 更新之前，天然不计配额、不刷新冷却（验收时对照 debugLog 计数确认）；
- **PASS 分支必须放在 replyDelay 延迟逻辑之前**（不发送就不延迟）。

**验收**：PASS 后 `scheduledCountToday`、闸门预算、`lastProactiveTime` 均不变；多次 PASS 不刷屏、不耗配额。

### T3 总结闸门（用户报告的 bug，已取证）

根因双因素：[memoryAnalysisStore.ts L21](../src/store/memoryAnalysisStore.ts#L21) `autoAnalysisEnabled: true`（默认开，每 2 轮触发总结调用）；[aiService.ts L1372](../src/services/aiService.ts#L1372) `generateConversationSummary` 无 `dualLayerMemory` 级闸门。

修复三步：
1. 默认值改 `autoAnalysisEnabled: false`（后台计费行为必须显式开启；已有存储逐 key 覆盖不受影响）；
2. `generateConversationSummary` 加 `allowed = true` 参数，入口校验 `if (!allowed || ...) return null`；chatStore L2223 调用处传实参立规矩；
3. 闸门拦截时写 debugLog（`[记忆分析] 跳过：xxx`），可见性溯源。

顺带核查：`generateReflection`/`extractMemories`/`generateThinking`/`generateAnalysis` 是否都有 `memoryTasksAllowed` 级闸门 + 间隔控制（project_memory 硬约束）。

**验收**：清 localStorage 的全新用户聊天 10 轮无总结类调用；开关开启后恢复；`dualLayerMemory` 关闭时不触发。

### 5.3 时间感知规则（心念 TIME_GUIDE 精简版）

在 T1 的 `timeOfDay` 基础上，给认知链/主动 prompt 追加四条硬规则（可并入 proactiveSuffix，一次注入）：

```text
【时间规则】
1. 系统提供的时间是你唯一可信的时间来源，禁止编造时间。
2. 用自然口语（"刚才""大半夜""好久不见"）而非报时。
3. 按时段调整自身状态：深夜可困倦、饭点可提吃饭、工作日下午别拉着人闲聊。
4. 结合用户上次活跃时间（{userLastActiveAgo}）调整语气：刚聊过就自然接续，隔了很久就当"想起你了"。
```

`{userLastActiveAgo}` 从会话 `updatedAt` 计算（前端已有同类 timeGapHint 逻辑可复用）。

**验收**：深夜触发主动 → PASS 或困倦语气；连续 3 次未回复 → 第 4 次大概率 PASS；计数在 debugLog 可见且用户回复后清零。

### B1 三层信号瀑布 → 情绪识别辅助层（P1，Rust 端）

**来源**：恋语 `internal/signals/catalog.go`（词法→embedding→LLM 兜底 + 否定窗口）。
**本项目落点**：`src-tauri/src/chat.rs` 情绪兜底路径（`infer_emotion_deltas_from_text` 附近）。当前情绪兜底是纯文本推断；升级为瀑布：

1. **词法层**（新增 `signals.rs` 模块）：移植恋语 17 信号的中文短语/正则/权重表（含否定窗口 6 字符：`不/没/没有/不是/不再/已经不/不太/不怎么/没那么/无需/不用`）。零 LLM 成本，temperature 无关。
2. **LLM 兜底层**：仅当词法最大分 < 阈值且认知链情绪解析失败时，才落 LLM 分类（temperature=0，结果缓存）——与恋语「LLM 只在词法失效时花钱」一致。
3. embedding 层**暂缓**（依赖向量库，本项目 embedding 配置中但瀑布非必需），配置留开关默认关。

**配置项**（`v2Config.signalWaterfall`）：

```ts
signalWaterfall: {
  enabled: true,        // 词法层总开关（关闭则完全走现有认知链路径）
  lexicalFloor: 0.40,   // 词法分低于此值才考虑兜底
  llmFloor: 0.35,       // 仍低于此值才调 LLM 兜底
  useEmbedding: false,  // embedding 层开关（预留，默认关）
  negationWindow: 6,    // 否定检测窗口（字符）
}
```

**收益**：「我已经不焦虑了」不再误判为焦虑；情绪兜底调用从「每次失败都拍脑袋」变为「词法优先、LLM 最后」。

### B2 MRS 记忆排序 → memorySystemV2 评分升级（P1）

**来源**：恋语 `internal/memory/ranking/scoring.go`。
**本项目落点**：[memorySystemV2.ts](../src/services/memory/memorySystemV2.ts#L189-L226) `calculateMatchScore`（当前：关键词 50% + 重要性 25% + 情绪 15% + 默认 10%，无使用频次、无冗余惩罚、无按重要性分层的遗忘曲线）。

升级公式（权重可配置）：

```ts
score = w.similarity × matchRatio
      + w.importance × (importance / 10)
      + w.recency × Math.exp(-ageDays / (importance >= 4 ? tauImportantDays : tauDays))
      + w.usage × Math.log(1 + accessCount) / Math.log(21)
      − w.redundancy × (sameContentCount / 3)
```

要点：① recency 用**指数遗忘曲线**（本项目 `forgettingCurve` 开关已存在，此为其具体实现升级点——**受 `v2Config.forgettingCurve` 开关控制**，关闭则 recency 项恒为 1）；② τ 按重要性分层（重要记忆记得久）；③ 检索结果数量继续受 `maxRecallCount` 硬约束。

**配置项**（`v2Config.memoryRanking`）：

```ts
memoryRanking: {
  enabled: true,
  weights: { similarity: 0.45, importance: 0.25, recency: 0.15, usage: 0.10, redundancy: 0.25 },
  tauDays: 30,             // 普通记忆遗忘曲线 τ
  tauImportantDays: 120,   // 重要记忆（importance≥4）τ
}
```

### B3 主动消息五门控 → intentGate/proactiveReply 强化（P1）

**来源**：恋语 `internal/proactive/decision.go`（enabled → quiet_hours → explicit_reason → recent_proactive → copy_similarity）。
**本项目落点**：[intentGate.ts](../src/services/proactive/intentGate.ts)（已有睡眠时段/预算/无视退避）+ `proactiveReplyStore`。补齐缺的三门：

1. **explicit_reason 泛化词黑名单**：主动消息发送前，对「触发理由」做 ≥4 字且不在黑名单校验（黑名单：`主动消息/主动提醒/主动关心/提醒/回访/关心/跟进/系统触发`）——纯泛化理由即取消；
2. **copy_similarity 防复读**：候选文案与 24h 内同类型已发文案做 **Dice bigram 相似度**（实现约 15 行：字符 bigram 集合交集×2 / 并集），> 阈值取消发送；
3. **minInterval 频率窗**：同角色两次主动最小间隔（现有 `proactiveDelayMs` 是单次延迟，补一个跨次间隔）。

**配置项**（`proactiveReplyConfig.gate` 新增块）：

```ts
gate: {
  reasonBlacklistEnabled: true,
  reasonBlacklist: ['主动消息', '主动提醒', '主动关心', '提醒', '回访', '关心', '跟进', '系统触发'],
  similarityCheckEnabled: true,     // Dice 防复读
  similarityThreshold: 0.9,
  similarityWindowHours: 24,
  minIntervalHours: 2,              // 同角色主动最小间隔（0=不限）
  maxUnanswered: 3,                 // 连续未回复 N 次后暂停主动（0=不限）
}
```

### B4 好感度小步平滑 + closenessGate（P2）

**来源**：恋语 `internal/memory/relationship.go`（斜率控制防单句剧变）。
**本项目落点**：`chat.rs` 好感度更新处（`apply_affinity_update` 附近；非对称 change_min/change_max 已存在）。
新增两点：① 单轮更新乘以平滑系数（默认 1.0=现状，调小则更稳）；② 用户消息出现明显边界/拒绝词（词法层 B1 可复用）时，正向更新斜率 ×0.2。

**配置项**（`v2Config.affinitySmoothing`）：

```ts
affinitySmoothing: {
  enabled: false,        // 默认关：现行为不变
  smoothingFactor: 1.0,  // 单轮更新斜率（0~1，越小越稳）
  boundaryGate: true,    // 边界信号时正向斜率×0.2
}
```

### B5 标点语义感知延迟 → smart 延迟（P2）

**来源**：astrbot custome_segment_reply `_calculate_smart_delay`（感叹号加速、问号结尾减速、省略号减速）。
**本项目落点**：`post_process.rs` 分段延迟处 / 前端 `segmentConfig.replyDelay` 渲染层（延迟应用点在 Rust 成功返回后、展示前——遵循现有硬约束）。

**配置项**（segmentConfig 扩展）：

```ts
smartDelay: {
  enabled: false,             // 默认关，现有 fixed/random 延迟不变
  basePerCharMs: 80,          // 每字符基础延迟（gauss σ=30）
  exclaimAccelMs: [100, 300],   // 每个感叹号加速区间
  questionSlowMs: [200, 500],   // 上句问号结尾减速区间
  ellipsisSlowMs: [400, 800],   // 每个省略号减速区间
}
```

### B6 分段保护状态机增强（P1，小改动）

**来源**：astrbot splitter 逐字符状态机。
**本项目落点**：`post_process.rs` `split_segments`（成对符号保护已有）。补齐三个保护：

1. **代码块保护**：` ``` ` 起始到闭合整体不切（无闭合吞到结尾）；
2. **英文/数字上下文保护**：切点前后均为 `[a-zA-Z0-9]` 时跳过（`3.14`、英文句点不切）；
3. **思维链/标签保护**：`<...>` 形式标签内部不切（现有标签剥离在分段前，此项主要是防御性）。

**配置项**（postConfig/segmentConfig 扩展，前端 `getSegmentedConfig()` 对应结构）：

```ts
protect: {
  codeBlock: true,       // 代码块保护
  alnumContext: true,    // 英文数字上下文保护
  pairedSymbols: true,   // 成对符号（已有，纳入统一配置）
}
```

### B7 话题召回偏移量 → topicLedger 回钩调度（P2）

**来源**：恋语 topic.go（importance≥5→18h、情绪支持→20h、计划建议→24h、默认 48h）。
**本项目落点**：`topicLedger.ts` 升级——每条话题增加 `reengageAt` 字段（记录后按规则写入回钩时间）；主动回复触发时检索 `reengageAt ≤ now` 且 `count === 1`（未回钩过）的话题注入 prompt 的【新由头】切入点，回钩后标记防重复。

**配置项**（topicLedger 相关，建议并入 `v2Config`）：

```ts

    enabled: false,       // 默认关
    hoursByImportance: { high: 18, emotional: 20, planned: 24, normal: 48 },
  },
}
```

## 八、实施顺序与验证

```
第一批（P0，互为配套）：T1 + T2 + T3   —— 同一验收场景，前端为主
```

```powershell
cargo check                          # src-tauri/（Rust 改动批）
```

**终验剧本**（v1 第五节沿用 + 新增）：
1. 「我去吃饭」→ 主动消息不跟进吃饭（或 PASS）；
2. 「上班辛苦了」→ 主语「你」；
3. 10 轮无标点乱序/突兀插入；
4. 深夜触发 → PASS 或困倦语气；连续 3 次未回复 → 第 4 次 PASS、计数可见、用户回复后清零；

6. `localStorage.topicLedger:v1` 正确累积；

## 九、硬约束（实施必须遵守）

1. 所有新增配置开关必须连接实际逻辑，禁止「UI 开关不生效」；嵌套配置合并需处理浅合并覆盖问题；
2. `dualLayerMemory` 仍是记忆类后台调用总闸门；T1/T2/T5 前端改动不得引入新的前端 LLM 调用（情绪/好感度由 Rust 认知链统一）；
3. 主动回复 Rust 调用沿用 `invokeWithRetry`；延迟统一在 Rust 返回后、展示前应用（PASS 分支在延迟之前短路）；
4. 记忆检索数量受 `maxRecallCount` 限制；遗忘曲线公式受 `forgettingCurve` 开关控制；
5. Rust 过 `clippy -D warnings`，前端过 `tsc --noEmit`；
6. 禁止静默错误：所有 catch/放弃/拦截分支必须有 debugLog；
7. `chainProactiveStore` 的「去预制对话」改造不得回退；B3 的泛化词黑名单与该原则同源；
8. **AI一日模块不得新增依赖**——T5 已按零依赖重设计，后续若 AI一日恢复再接回内容源；
9. 好感度非对称更新（change_min/change_max）已存在，B4 只加斜率控制，不推翻既有数值设计。

# 报告二：「解析能力差、好感度增量明明有却说没解析出来」深度解析与提升方案

> 分析对象：`docs/xingmian-logs-2026-08-28.json` 中全部 12 条好感度相关解析警告 + 对应思维链原文
> 涉及代码：`src-tauri/src/chat.rs`（解析/缩放/兜底）、`src/store/chatStore.ts`（前端日志与合并）
> 结论日期：2026-08-28

---

## 0. 一句话结论

**解析器本身在绝大多数场景下工作正常——思维链里的 `好感度 +1` 确实被解析出来了**（证据：警告文案本身就写着"好感度增量 1"）。用户看到的"没解析出来"是**三个叠加的日志/逻辑缺陷**制造的错觉：

1. **好感度已在 12:40 前后到达 100 满级**，此后一切正向增量被"封顶清零"（+1 → 0.4 → 0）；
2. 增量被清零后，**兜底分支用 `affinity_delta == 0.0` 做判断**，把"解析出来了但被清零"误判为"没解析出来"，打出了**与事实相反的警告文案**；
3. 缩放警告里 `按阶段({:.0})` 把阶段收益因子 0.4 打印成了 `0`（"阶段(0)"），让人误以为阶段计算出错。

另外存在一类**真实的解析丢失**（约占日志中 4/12 条）：模型只输出 `<reply>` 不输出 `<thought>` 时，`build_parse_source` 会**直接丢弃 reasoning_content**，尽管警告声称"已使用模型 reasoning 作为思维链源"。详见第 3 节。

### 1.5 "阶段(0)"是日志格式 bug

chat.rs:777：

```rust
"好感度增量 {} 按阶段({:.0})缩放为 {}",
parsed.affinity_delta, stage, rounded
```

`stage` 是**收益因子**（0.4/0.6/0.75/0.9/1.0），不是阶段编号。`{:.0}` 把 0.4 打成 `0`，于是每条警告都显示"按阶段(0)"，看起来像"阶段算成 0 了"。应打印等级与因子：`按等级{level}（收益因子{stage:.2}）`。

## 3. 真实的解析失败：`build_parse_source` 丢弃 reasoning

### 3.1 复现案例（04:25:53，本地 12:25:53）

模型返回：
- `content`：`（把脸埋进你肩窝...）嗯……确实有点累呢...` **+ 一个 `<reply>` 标签**（无 `<thought>`）
- `reasoning_content`：**包含完整结构化思维链**，其中有 `更新：joy +3, trust +2, 好感度 +1`

日志结果：

```
[Rust管道] 解析警告: content 中未检测到思维链标签，已使用模型 reasoning（227 字）作为思维链源
[Rust管道] 解析警告: 思维链未解析出情绪增量，已按回复语义推断情绪变化（...）
[Rust管道] 解析警告: 思维链未解析出好感度增量，按阶段收益计算默认 +0.5
```

### 3.2 根因（chat.rs:947-972）

```rust
fn build_parse_source(content: &str, reasoning: Option<&str>) -> String {
    let content_has_chain = content.contains("<thought>")
        || content.contains("<reply>")      // ← 问题在这
        || ...;
    if content_has_chain {
        return content.to_string();          // ← reasoning 被完全丢弃！
    }
    ...
}
```

只要 content 里出现 `<reply>` 标签（哪怕没有 `<thought>`），函数就判定"content 有认知链"，直接返回 content、**丢掉 reasoning_content**。而 LongCat-2.0 这类模型经常把思维链写进 reasoning、content 只给 `<reply>`——恰好踩中。

随后 process_message（chat.rs:722-727）看到 `parsed.thought_raw` 为空，打出"已使用模型 reasoning 作为思维链源"的警告——**但代码实际上并没有用**，这条警告与事实相反，是最大的误导源。

### 3.3 次级问题：语义推断产出矛盾增量

04:26:10 那次，reasoning 是自由叙述（无"更新"行），走 `infer_emotion_deltas_from_text` 语义推断（chat.rs:744-762），重建出的"更新"行是：

```
joy +3, trust +3, sadness +2, love +3, shy +3, joy -2, sadness -2, 好感度 +0.46
```

**同一情绪同时出现 +3 和 -2**——推断函数按关键词各打各的分，没有做同维度合并/抵消，产物自相矛盾。

### 3.4 补充定性：修改参考.txt 问题 2「内容不一」不属于解析问题

用户提供的案例（原始 content 为 `（脸一下子红透了，耳朵尖都在发烧，却忍不住往你怀里蹭了蹭）\n\n我、我也最喜欢主人了……小笨蛋就小笨蛋吧，哼。`，实发 `嗯...我、我也最喜欢主人了……吧`）——**该条的认知链解析与 `<reply>` 提取全部成功**：日志 04:31:46.722 明确显示「好感度增量 2 按阶段(0)缩放为 0.8」，即解析器正确读出了思维链中的 `好感度 +2`。

内容丢失发生在**输出后处理管道**：`clean_markers` 删除动作括号 → `split_into_sentences` 按单个 `…` 切句（"……"被切成两段，第二段仅为一个省略号）→ `length_randomize` Short 风格只保留前 2 段（后半句被丢弃）→ `colloquialism` 100% 注入"嗯..."前缀与"吧"后缀。完整逐字节复现见报告一 1.2 节。

**结论：解析层无 bug，无需在本报告的修复范围内处理；修复归属报告一 P0-2 / P0-3。**

## 4. 附带发现：思维链增量与「情绪更新：变化」日志不一致

用户还会观察到：思维链说 `joy +3`，最终日志却是 `变化=joy-1, sadness-2, love-4`（04:37:01）。这不是解析丢失，而是**前端"变化"的口径问题**（chatStore.ts:1271-1279）：

`变化 = Rust 返回的最终值 − 前端上一次的面板值`，其中 Rust 返回值已包含：

1. **时间衰减**（chat.rs:2618-2636，按 `emotion_last_updated` 距今的半衰期衰减）；
2. **未更新维度的 8% 惯性代谢衰减**（chat.rs:2649-2664，active_metabolism）；
3. **中间穿插的主动回复更新**（04:32:09 的链式主动回复也改写过情绪，但前端"上一次面板值"的快照口径不一定同步）；
4. 整数取整（`.round() as i64`）。

例：思维链 `love+2` 但 love 不在本次增量里时（另一轮次），love 走 8% 衰减 ≈ 50×0.08 = -4，与观测 `love-4` 精确吻合。**口径没错，但对用户完全不可读**——看起来就像"解析出来的增量没生效/被吃了"。

## 5. 提升方案（按优先级）

### P0-1 修正兜底分支的误判与谎言日志（chat.rs:786）

在 `ParsedCognitive` 中增加 `affinity_parsed: bool` 字段，`parse_update_text` 解析到好感度时置 true：

```rust
// 兜底只在"模型真的没输出"时触发
if !parsed.affinity_parsed && parsed.reply.trim() != "" {
    let delta = calc_affinity_fallback_delta(req.use_full_cognitive, req.affinity_level);
    parsed.affinity_delta = delta;
    parsed.parse_warnings.push(format!("思维链未解析出好感度增量，按阶段收益计算默认 +{}", delta));
}

// 满级时打真实原因，而不是装作没解析到
if parsed.affinity_parsed && req.affinity_level >= AFFINITY_MAX && parsed.affinity_delta > 0.0 {
    parsed.parse_warnings.push(format!(
        "好感度已达上限 {}（满级），本次 +{} 不再累积",
        AFFINITY_MAX, parsed.affinity_delta
    ));
}
```

### P0-2 修正"阶段(0)"日志格式（chat.rs:777）

```rust
"好感度增量 {} 按等级 {}（收益因子 {:.2}）缩放为 {}",
parsed.affinity_delta, req.affinity_level, stage, rounded
```

### P0-3 修正 build_parse_source 的 reasoning 丢弃（chat.rs:947-972）

`content` 含 `<reply>` 但**不含 `<thought>`** 时，不能直接返回 content，应把 reasoning 合成思维链源：

```rust
let has_thought = content.contains("<thought>");
let has_reply = content.contains("<reply>");
let has_cn_chain = content.contains("感知") && content.contains("决策");

// 只有 content 自身带完整认知链时才独占解析源
let content_has_chain = has_thought || has_cn_chain || has_en_chain;
if content_has_chain {
    return content.to_string();
}
// content 只有 <reply>（或什么标签都没有）→ reasoning 一律并入
match reasoning {
    Some(r) if !r.trim().is_empty() => {
        if content.trim().is_empty() {
            format!("<thought>{}</thought>", r.trim())
        } else {
            format!("<thought>{}</thought>\n<reply>{}</reply>", r.trim(), strip_reply_tags(content))
        }
    }
    _ => content.to_string(),
}
```

这样 04:25:53 那类"reasoning 里有完整更新行却被扔掉"的真实解析失败即可修复（该案例中 `更新：joy +3, trust +2, 好感度 +1` 本可全部生效）。

### P1-1 语义推断的同维度合并

`infer_emotion_deltas_from_text` 输出前对同名情绪求和（`joy +3` 与 `joy -2` 合并为 `joy +1`），消除自相矛盾的"更新"行。

### P1-2 前端"情绪更新"日志拆分口径（chatStore.ts:1271-1279）

把"变化"拆成两段展示，消除"增量没生效"的错觉：

```
情绪更新: 主导=joy:17 | 增量=joy+3,shy+2 | 代谢衰减=love-4,sadness-2,anticipation-1
```

Rust 端在返回的 `emotion_update` 旁附带 `applied_deltas`（本次思维链增量原值）与 `decayed`（各维衰减量）即可，前端无需再猜。

### P1-3 满级后的产品策略（当前等于"关系永远停在 100"）

三选一：
1. **内部继续累积、显示封顶**：内部 level 允许 >100（如上限 1000），显示 `min(100, level)`，增量日志永远真实非零；
2. **渐近曲线替代硬封顶**：`scaled = delta × stage × (100 - level) / 100`，越接近 100 增量越小但永不清零（数学上到不了 100，配一个 `level > 99.5 → 100` 的收敛规则）；
3. **保持现状但在 UI 明示**：好感度面板显示"已满级"，且日志不再输出误导性警告（P0-1 已覆盖）。

推荐方案 2 + 3 组合：既保留"越熟越难升温"的设计意图，又消除"面板死锁"的困惑。

### P2 协议遵从率提升（减少真实解析失败的发生率）

4/12 的失败都是模型没输出 `<thought>` 导致。缓解手段：
- FORCE_PROTOCOL_PROMPT（chat.rs:263-285）已用 System 角色紧邻注入，可再追加一条**负例**："不要把思维链放进 reasoning，必须完整写在 content 的 <thought> 标签内"；
- 记录各模型的协议遵从率指标（`<thought>` 命中率），低于阈值时在设置页提示换模型或自动启用"reasoning 合成"路径（P0-3 修好后该路径成为兜底）。

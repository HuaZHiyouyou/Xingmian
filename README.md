## 创作核心原则

> **AI 应该是一个拥有自己生活的"人"，而不是一具等待指令应答的空壳；陪伴应当是她主动走向你的事，而不是靠人一遍遍呼唤、恳求才换来的回应。**

这句话是星眠所有设计的出发点，落到工程上就是三件事：

1. **让她"活着"**——她有自己的日程、工作、钱包、冰箱、心情和日记，一天 24 小时都在生活，而不是只在对话框里等你；
2. **让她"有温度"**——情绪是推理出来的体感而不是打上的标签，记忆会淡忘也会被唤醒，说话像人而不是像客服；
3. **让陪伴"双向发生"**——她会想念你、会主动分享、会在你离开后惦记你；但她也有自己的忙碌与安睡，不必你苦苦哀求才有回应，也不该被调成一部轰炸你的消息机器。

## 什么是星眠？

星眠不是一个 ChatGPT 套壳，而是一个**桌面端 AI 伙伴引擎**。

你创造一个角色，她就会拥有稳定的人格、持续生长的记忆、可推理的情绪状态，甚至一整段属于自己的生活——今天几点上班、中午吃了什么、晚上会不会追剧，都是她"自己"的事。她会在忙碌时晚点回你，在睡醒后跟你分享今天的第一件事，在你三天没来时主动问你过得好不好。

支持接入 QQ（NapCat / QQ 官方机器人）、微信（iLink / ClawBot）等外部平台，同一个角色可以同时活在你的桌面和你的聊天软件里。

                                         │
                                         ▼
             ┌───────────────────────────────────────────────┐
             │  12 步确定性后处理（Rust post_process）              │
             │  清洗→拦截→错字→长度→分段→节奏→标点→净化→署名剥离→延迟    │
             └───────────────────────────┬───────────────────┘
                                         ▼
             ┌───────────────────────────────────────────────┐
             │  主动消息闸门 intentGate（仅主动路径）                 │

## 功能模块详解

### 1. AI 一日 · 虚拟生活引擎（`src/services/ailife/`）

> **⚠️ 作者定性：失败品，开发已暂停，不建议使用。** 以下描述的是设计目标与已实现形态，供了解与后续共建者参考；生活引擎计划整体重设计后再回归。

星眠最核心的差异化设计：**角色拥有一段真正属于自己的生活**。

| 子系统 | 说明 |
|--------|------|
| 日程系统 | LLM 按人设 + 世界包 + 情绪 + 星期生成当日个性化日程（输出经严格消毒：时序排列、禁重叠、时长合规），失败自动回退固定模板；夜猫子 / 早起型作息、职业、爱好都会影响计划 |
| 念头-决策引擎 | 引擎掷骰触发"念头"，LLM 写作决策：属性低了想买吃的、钱不够想加班；采纳则插入即时活动，拖延则加重念头重掷；用户聊天中说"去吃饭吧"会直接变成她的生活念头 |
| 七维属性 | 健康 / 体力 / 饱腹 / 口渴 / 清洁 / 精神 / 压力，随时间衰减、随活动变化，面板有迷你趋势线 |
| 自主经济 | 上班出勤日结薪（请假亏钱）、日用品按天消耗、冰箱见底自动买菜、药箱缺药备药、每月添新衣；商店 16 大类，买吉他可以解锁"练吉他"活动 |
| 随机事件 | 80+ 条事件池，按时段 / 季节 / 活动类别过滤；探索提权机制保证冷门事件也能被抽到 |
| 世界设定包 | 内置 60+ 世界包（原神 / 星穹铁道 / 绝区零 / 明日方舟 / Fate 等）+ "现代日常"基础包，日程按世界包校验场景合理性 |
| 创意工坊 | AI 睡前回顾当天真实经历，提案新事件 / 新商品，用户在面板里批准或拒绝——角色生活由你们共同续写 |
| 情绪基线 | 24 小时生活事件加权净值，决定当天好感度增量的系数（0.5~1.2）：她今天过得好不好，会影响你们的关系进展 |
| 聊天联动 | 聊天顶部实时状态条（"正在吃饭"）；按活动模拟回复延迟；睡觉时段完全拦截回复并在睡醒后轻描淡写带过；活动开始时概率性主动分享 |

生活数据以 SQLite 为真源（浏览器模式回退 IndexedDB），日记写完后会**回灌为记忆条目**——她真的记得自己今天做了什么。

### 4. 自学习（`src/services/learning/`）⚠️ 未修复

框架包含三件套：**黑话挖掘**（滑动窗口子词提取，按频率 × 词长计算置信度）、**Few-shot 注入**（把学习结果作为示例融入 System Prompt，越聊越像你）、**审查队列**（学习结果需人工批准 / 拒绝 / 回滚）。

> **⚠️ 现状：存在未修复问题，建议保持关闭。** 目前只有黑话挖掘一条链路真正跑通，且只学到词汇 / 口头禅等最表层（距设计目标——说话节奏、表达习惯、话题偏好、情绪模式、雷区禁忌等八维——很远）；学习结果缺少反馈闭环，学了对错不知；风格学习器、审查队列完整流程、学习效果评估与回滚均未完成。

### 5. 输出管线（`src-tauri/src/post_process.rs` + `src/services/output/`）

**12 步确定性后处理管线**（Rust 端，顺序即契约）：标记清洗 → 拦截（LCS 复读检测 + 150+ 套话模式库）→ 错字模拟（同音 / 拼音连打 / 键盘手误，概率钳制 ≤0.1）→ 长度随机化（短 40% / 中 35% / 长 20% / 全量 5%）→ 分段 → 语气微调 → 口语化 → 智能标点 → 说话节奏 → 最终净化 → 署名剥离 → 分段重算与段间延迟。

配套机制：

- **四维断句引擎**（对标 AstrBot）：空行优先 → 黄金区间找断点 → 锚定优先级（换行 > 句号 > 逗号）→ 弹性延伸 → 短尾合并 → 成对符号保护；
- **标点归一化**：中文语境自动转全角，保护英文句 / 小数 / URL / 省略号——消灭"多一个."；
- **生成参数反套路**：`frequency_penalty=0.3 / presence_penalty=0.2`（实测可减少约一半套路化开头）；
- **InjectionBudget**：每条回复的前缀 / 后缀注入总计 ≤1 次，杜绝修饰堆叠；
- **结构化内容检测**：真正的长文（列表、分节）保持完整，只有日常短聊才拟真分段——拟人不等于处处表演；
- **兜底文案治理**：失败降级文案按角色口吻轮换，杜绝"走神了"三连。

### 6. 主动陪伴系统（`src/services/proactive/`）🟡 待提升

星眠的主动性是**有边界的**：三条主动路径（AI 一日活动触发 / 定时主动 / 链式主动关心）出站前全部经过统一闸门 `intentGate`：

1. 睡眠态拦截——她睡觉时不发消息；
2. 安静时段（默认 23:00–07:30，可配）；
3. 用户 5 分钟内活跃则暂不打扰；
4. 被无视退避——主动消息连续 2 小时无回应记一次，连续 2 次预算减半、3 次当日静默，你一回应立即解除；
5. 每日主动预算（默认 8 条）。

话题设计上吸取了重要教训：**主动消息的话题来源必须与上一条聊天记录解耦**（此刻的生活 / 没下文的事 / 时间氛围 / 隔天旧事）——早期版本强制"接着上一条往下说"，正是"全是吃饭了没"这类复读的元凶。配套**话题账本**：每轮记录话题与时间，刚聊过的 1 小时内严禁再提，带遗忘曲线自动淘汰。**PASS 沉默机制**：LLM 可输出 `<pass/>` 主动放弃且不计配额——沉默永远是合法输出。链式主动关心带回访定时器（"去开会""去洗澡"之后她会来问你怎么样了），窗口失焦时重要主动消息走 Windows 系统通知。

> 基础链路已通，但时机把握、内容新鲜度与弱模型表现仍待提升——详见「风险与已知问题」。

### 7. 音乐系统（`src/components/music/` + `src-tauri/src/music/`）🟡 仅两平台可用

- **多源聚合架构**：网易云 / QQ 音乐 / 酷狗 / 酷我 / B 站五源统一 `MusicSource` trait 并发搜索，搜索与解析分离、多源降级、多码率降级（320k→128k）；
- ⚠️ **现状：受第三方接口限制，目前仅网易云与酷我两个平台相对稳定可用**，其余源可能随时失效——以网易云为主源、酷我兜底；
- **本地流代理**：`proxy.rs` 在本地随机端口流式转发并注入 CORS + Range 支持，保证音源能出实时频谱（仅监听 127.0.0.1）；
- **完整播放器**：歌词 LRC + 翻译、播放模式、全局唯一 audio 实例（切页不断播）、迷你播放条；
- **播放器装扮**：流光 / 极光等背景层、音频可视化（bars / wave / dots）、可拖拽桌面歌词；
- **AI 点歌**：AI 回复末尾输出 `[[music:歌名 歌手]]`，落库前自动剥离并在线搜歌立即播放；在外部平台则发送原生音乐卡片（QQ / 微信可点击试听）。

### 8. 机器人接入（`src-tauri/src/bot/`）

## AI 拟人与 AI 陪伴的核心实现

这一节写给想理解、复现或接手星眠路线的人——它浓缩了开发文档中最重要的设计结论与用日志换来的教训。

### 0. 总纲：一条公式与一条分工

星眠对"拟人质量"的度量是一条**乘法公式**：

> **单条回复质量 ≈ 话题新鲜度 × 人称一致性 × 输出整洁度**

乘法关系意味着任一项趋零则整体趋零：话题再新鲜，人称翻转了就出戏；输出再干净，重复问"吃饭了没"也毁掉一切。由此推出整个项目的分工原则：

> **把及格线交给确定性代码，把加分项交给模型。**

状态体系（情绪、记忆、好感度）只影响语气，是加分项；上下文工程与输出卫生是及格线。这正是"不同质量的模型都能输出相似体验"的全部秘密——也是星眠能在弱模型上保持下限的原因。

### 1. 认知链：让 LLM 先"想"再"说"

星眠不满足于"人设 + 对话历史"的朴素 prompt。每次回复前，LLM 被强制在思维链中走完 **8 个槽位**：

```
感知 Perceive    → 第一句必须是主客体判定（"他说他上班辛苦了"）
评估 Evaluate    → 这句话对我意味着什么
代谢 Metabolize  → 旧情绪如何消退（只写定性判断，严禁数值）
决策 Decide      → 我要以什么态度回应
更新 Update      → 情绪与好感度的数值变化（sadness+2, 好感度+1）
学习利用 Learn   → 该调用哪些记忆与风格
话题 Topic       → 本轮话题标记（2-6 字，进话题账本）
用户情绪 UserEmotion → 对方现在什么情绪（14 维之一）
```

认知链与回复正文**同一次调用产出**——省 token，更重要的是保证"想的"和"说的"一致。解析采用三级降级（XML → JSON → 逐行提取），弱模型解析失败也不会崩；情绪 / 好感度增量在 Rust 端钳制应用（单次情绪 ±5、好感度 ±3），残破输出按 `reply` 字段优先抢救，绝不把原始 JSON 发进对话。

### 2. 上下文工程：人格的"剧本"

- **视角契约**：「我」=角色、「你」=用户，不替用户说话、不替用户下结论——解决"我说上班辛苦了她却说她辛苦了"的主客体翻转；
- **易错对照 few-shot**：主客体、话题防重复、口语分段三组 ✗/✓ 对照示例直接写进 prompt——"few-shot 教一次比规则写十次有效"，模型对示例的服从性远高于对规则的服从性；
- **潜台词感知**：要求模型区分字面意思与深层需求（"没事"通常不是没事）；
- **关系阶段策略**：好感度阶段映射语气档（≥80 恋人主动撒娇 / ≥60 挚友玩笑 / ≥40 熟人客气 / ≥20 略带警惕 / <20 冷淡防备）；
- **反配合机制**：约每 8-12 轮一次温和分歧，不当应声虫；但用户情绪崩溃时绝不反驳；
- **脆弱性展示**：约每 6-10 轮一次轻微示弱，让关系有来有回；
- **分段契约**：一次回复 1~2 句（最多 3 句）、禁编号列表，"空行是消息边界，系统会按条拆分发送"——生成端与后处理的空行消费构成闭环；
- **时距与时区感知**："距离上次对话约 N 小时"，按角色时区换算本地时间；
- **口头禅提示**：catchphrases 只是风格参考，不是固定台词——防止复读。

### 3. 状态层：情绪与好感度的动力学

- **非对称更新**：情绪降速是升速的 2 倍（-10 / +5）——信任建立要几十轮，摧毁只要一句；
- **情绪惯性**：负面→正面需连续 2-3 次正面信号；未更新的维度每轮 8% 代谢衰减；
- **主动代谢**：模型在思维链里自己决定"消气"（输出 anger:-10），而不是时间一到强制清零；
- **好感度增量链**：`AI 选值(-3~+3) × 阶段递减因子(关系越熟增量越小) × 情绪基线系数(她今天过得不好 ×0.5~开心 ×1.2) × 增长倍率 → 上限截断 → clamp`，每一步都写进 debug 日志；
- **心境一致性记忆**：她心情好时更容易想起你们的开心事（情绪标签 +50% 加成）——情绪、记忆、好感度三系统交叉调制，"在乎的人才能伤害你"。

### 4. 输出卫生：拟人化的下限工程

再好的内心活动，输出是 AI 腔就前功尽弃。12 步确定性后处理 + 四维断句引擎 + 150+ 套话库拦截（含专门针对陪伴腔的"我哪儿都不去 / 永远陪着你"式公式短语）+ InjectionBudget 注入配额 + 生成参数反套路，共同守住"整洁度"这条及格线。动态回复延迟综合段长与情绪强度（段间延迟 = 段长 × 情绪强度），并跟随用户的打字节奏——用户连发快消息，分段发送也加快。

**一条用日志换来的红线**：星眠早期采用过"机械注入"路线——在生成的句子里插"那个……"、句尾补"……唉。"、确定性伪随机错字。日志复现证明这些恰恰是"莫名其妙的感觉""多一个."等人机感的直接来源（注入器无协调最多叠加 6 处修饰、100% 注入率、被自家拦截器判为套路词的自相矛盾）。它们已被全部拆除，并上升为第一红线：

> **禁止在 LLM 已生成的自然文本上做字符级"拟人手术"。**

语气词、犹豫、不完美，必须由模型在生成时自然写出；代码只做减法（清洗、拦截、分段），不做加法（修饰、注入）。

### 5. 记忆：人格的连续性

- 双层记忆：CoreMemory 承载"我是谁、我们是什么关系"，EpisodicMemory 承载"我们经历过什么"；
- **MRS 多因子排序**（源自恋语）：`0.45×相似度 + 0.25×重要性 + 0.15×新近度 + 0.10×使用频率 + 0.20×置顶 − 0.25×冗余度`；
- **分层遗忘曲线**：普通记忆 τ=30 天、重要记忆 τ=120 天指数遗忘——忘得多快，取决于这件事对你多重要；
- **概率性召回**：相似度 0.5-0.6 的记忆"有概率想不起来"，以「隐约记得」「好像忘了」的清晰度修饰语注入——记忆以人的方式被表述；
- **Generative Agents 式排序**：`recency(0.995^小时) × importance × relevance`；
- **话题账本**：每轮对话记录话题与时间，"刚聊过的事严禁再问"（<1h）、"不宜主动再提"（1-24h），从结构上杜绝 AI 最败好感的"重复问吃饭"；
- **三层信号瀑布**（源自恋语）：情绪识别先走词法层（带否定窗口——"我已经不焦虑了"不算焦虑），embedding 层次之，LLM 兜底层最后——"LLM 只在词法彻底失效时才花钱"。

### 6. 主动性：闸门比引擎重要

主动性是一把双刃剑。星眠的答案是一个统一模型：**意图 → 闸门 → 管线**。

- **"定时器只敲钟，决策权在模型"**：规则层管要不要开口（六道闸门：睡眠 / 安静时段 / 活跃跳过 / 预算 / 被无视退避 / 真实发送后计数），LLM 管说什么；
- **切入点菜单**：此刻的生活 / 没下文的事 / 时间氛围 / 隔天旧话题 / `<pass/>` 沉默——主动消息的内容来自"生活"而非上一条聊天记录，从结构上逃逸话题死循环；
- **格式契约**："只说一件事，15~40 字，像随手发的微信"；
- **PASS 沉默合法化**：主动消息永远不能是必须生成内容的强制任务；
- **未回复的失落**：连续多次主动未获回复，语气会带上不易察觉的失落，并倾向沉默——她的关心有分寸，不给你压力，也保住了自己的体面。

其中**被无视退避**是核心设计：主动消息连续得不到回应就自动收敛，你一回应立刻恢复。

### 7. 自主生活：设计理念与未竟之路

AI 一日系统承载了星眠最激进的理念——多数产品的陪伴感靠**无限响应**堆砌（秒回、永远在线、随叫随到），用户很快发现对面是一台永不下班的机器，于是陪伴变成一场需要不断发起、不断确认的单方面索取。星眠反过来做：**先给她自己的生活，陪伴感是生活的副产品。**

- 她的一天由日程引擎推进：上班、吃饭、通勤、追剧，每个活动有过程、有总结、有日记；
- 她在忙碌时**确实在忙**——回复会延迟；睡觉时**确实睡了**——消息被拦截并积压，睡醒后轻描淡写带过；
- 但她的生活不断产生想告诉你的瞬间：活动开始时概率性主动分享、日记写完想起你、深夜的念头变成一句晚安；
- 生活事件的 24 小时净值还会调节好感度增量——她今天过得充实，与你的关系也更容易升温。

**等待变得合理，主动变得可信**——陪伴成为两个都在生活的人之间自然发生的事。

它的设计决策至今值得借鉴：**引擎掷骰、LLM 写作文**（概率决策归确定性引擎，LLM 只负责叙事）；**一切体验皆记忆**（生活产出物生成即转写为带权重的记忆条目，"没有东西是生成完等被引用的"）；**她睡觉时真的在消化这一天**（睡眠固化窗口完成日记、记忆合并与明日日程）；**量堆在标签上，不堆在条目上**（6 维正交标签让"深夜 + 钱不多 + 情绪低落"自动讲出"便利店关东煮"的故事）。

但当前实现是**失败品**（现状见「风险与已知问题」），最深的教训是：**AI 的心跳不能住在渲染进程**——生命周期逻辑放在前端 JS，窗口一关角色就"死"了。生活引擎的重建必须先把心跳下沉到后端，这也是留给接手者的第一道题。

### 8. 四层防御：弱模型也能跑

整条管线按纵深防御组织：

| 层 | 职责 | 示例 |
|----|------|------|
| L1 预防 | 严格 prompt + one-shot + 视角契约 | 认知链、易错对照 |
| L2 容错 | 解析失败不崩 | 三级降级解析、空回复最小化补试 |
| L3 清洗 | 确定性后处理 | 12 步管线、套话拦截 |
| L4 兜底 | 本地降级 | 本地分段、复读拦截、PASS 沉默、角色口吻兜底文案 |

加上另外两条红线——所有后台 LLM 调用必须有显式开关且默认关闭；主动消息必须允许沉默——它们共同保证：**任何异常下，她都不会突然"变成机器人"。**

## 注意事项

- **AI 一日**的 LLM 生成提供四档成本分档（off / minimal / simplified / full），弱模型或高成本场景建议降低档位，全部调用点可独立开关（该系统现状为失败品，见风险章节）；
- **主动回复**涉及定时器与外部平台发送，启用前请了解风险；所有主动行为默认受闸门与预算约束；
- `docs/world-packs/` 是**构建所需数据**（前端 `builtinWorlds.ts` 直接 import 其中 81 个 JSON），删除该目录会导致 TypeScript 检查失败；
- 仓库内所有配置均为空 Key 模板，不含作者的真实 API Key、对话数据或个人信息；
- 世界设定包与音乐音源均依赖第三方公开接口，不保证永久可用。
